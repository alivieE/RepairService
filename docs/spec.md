# Специфікація RepairService

Застосунок для приймальника сервісного центру: облік заявок на ремонт
пристроїв, розрахунок дедлайну й вартості, проведення заявки станами
та звіт про прострочені заявки.

## 1. Межі системи

| Входить | Свідомо не входить |
|---------|--------------------|
| облік заявок, позицій, клієнтів і прейскуранта | платіжний термінал, фіскальні чеки |
| дедлайн ремонту за пріоритетом заявки | графік роботи майстрів і робочі дні |
| вартість робіт і деталей з надбавкою за терміновість | облік складу деталей і закупівлі |
| проведення заявки станами за таблицею переходів | сповіщення клієнта SMS чи поштою |
| пошук заявок за станом, клієнтом і пріоритетом | розмежування прав користувачів |
| звіт «прострочені заявки» на дату | графічний інтерфейс, вебдоступ |
| збереження даних у файлі JSON | база даних |

## 2. Словник домену

| Термін | Ідентифікатор у коді | Значення |
|--------|----------------------|----------|
| заявка | `RepairTicket` | документ на ремонт пристрою; має стан, пріоритет і позиції |
| позиція заявки | `RepairWork` | робота або деталь: код, кількість, ціна за одиницю |
| вид позиції | `LineKind` | `Work` — робота майстра, `Part` — деталь |
| клієнт | `Customer` | людина, що здала пристрій у ремонт |
| прейскурант | `ServiceItem` | довідник робіт і деталей з цінами |
| пріоритет | `TicketPriority` | `Low`, `Normal`, `High`, `Urgent` |
| стан заявки | `TicketStatus` | `Received`, `InWork`, `Ready`, `Issued`, `Rejected` |
| дата прийняття | `RepairTicket.CreatedAt` | день, коли пристрій прийнято в ремонт |
| дедлайн | `RepairTicket.Deadline` | дата, до якої ремонт має бути завершено |
| строк ремонту | `PriorityRules.DaysFor` | кількість днів від прийняття до дедлайну |
| надбавка за терміновість | `PriorityRules.SurchargeOf` | частка, на яку зростає вартість робіт |
| вартість заявки | `RepairTicketService.TotalOf` | роботи з надбавкою плюс деталі, грн |
| прострочена заявка | `OverdueReport` | незавершена заявка, дедлайн якої минув |
| оплата при видачі | `RepairTicketService.Pay` | оплата, після якої пристрій видається |
| порушення правила | `DomainRuleException` | виняток домену з ідентифікатором правила |
