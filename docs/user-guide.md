# Посібник користувача RepairService

## 1. Запуск

```powershell
dotnet run --project RepairService.App
```

Після запуску видно версію і меню:

```
RepairService v1.0.0

1 — прийняти заявку   2 — додати позицію   3 — змінити стан
4 — оплатити й видати 5 — пошук заявок     6 — прострочені   0 — вихід
```

Пункт обирається цифрою й клавішею Enter. Меню повертається після кожної
операції; `0` або закриття вводу завершує роботу.

## 2. Прейскурант

У застосунку 60 позицій. Непарні номери — деталі `PRT-001`, `PRT-003`, …,
парні — роботи `WRK-002`, `WRK-004`, … Регістр коду не важливий
(`wrk-002` = `WRK-002`). Приклади цін: `PRT-001` — 130 грн, `WRK-002` — 300 грн.

## 3. Сценарії

### 3.1. Прийняти заявку (пункт 1)

```
> 1
Номер клієнта: 100
Модель пристрою: Lenovo IdeaPad 5
Пріоритет (Low, Normal, High, Urgent): Urgent
Заявку № 1 прийнято, дедлайн 20.11.2026.
```

Дедлайн = дата прийняття + строк за пріоритетом: Low — 10 днів, Normal — 5,
High — 2, Urgent — 1.

### 3.2. Додати роботу чи деталь (пункт 2)

```
> 2
Номер заявки: 1
Код позиції (наприклад, WRK-002 або PRT-001): WRK-002
Кількість: 1
Додано WRK-002 × 1. Вартість заявки: 390,00 грн.
```

Для Urgent вартість робіт зростає на 30 %, для High — на 15 %; деталі завжди
за ціною прейскуранта. Позиції додають лише до заявки в стані Received.

### 3.3. Провести заявку станами (пункт 3)

```
> 3
Номер заявки: 1
Новий стан (InWork, Ready, Rejected): InWork
Заявка № 1: стан InWork.
> 3
Номер заявки: 1
Новий стан (InWork, Ready, Rejected): Ready
Заявка № 1: стан Ready.
```

Дозволено: Received → InWork (якщо є позиції), InWork → Ready, Received або
InWork → Rejected. Стан Issued встановлюється лише оплатою (пункт 4).

### 3.4. Оплатити й видати (пункт 4)

```
> 4
Номер заявки: 1
До сплати: 390,00 грн.
Сума оплати, грн: 390
Заявку № 1 оплачено, пристрій видано.
```

### 3.5. Пошук і звіт (пункти 5 і 6)

```
> 5
Стан (Enter — будь-який):
Пріоритет (Enter — будь-який): Urgent
   № | Клієнт | Пристрій             | Пріор.  | Стан      | Дедлайн
   1 |    100 | Lenovo IdeaPad 5     | Urgent  | Issued    | 20.11.2026
> 6
Дата звіту дд.мм.рррр (Enter — сьогодні): 02.12.2026
Прострочені заявки на 02.12.2026
   № | Клієнт | Пристрій             | Пріор.  | Дедлайн    | Днів
   2 |    101 | Asus X515            | Low     | 29.11.2026 |    3
Разом прострочених заявок: 1
```

До звіту потрапляють лише заявки в станах Received та InWork; заявка,
дедлайн якої настає в день звіту, ще не прострочена.

## 4. Повідомлення про помилки

| Повідомлення | Причина | Що робити |
|--------------|---------|-----------|
| `Введіть ціле число, більше за нуль.` | номер клієнта, заявки чи кількість — не число або ≤ 0 | ввести додатне ціле число; запит повториться |
| `Значення не може бути порожнім.` | порожня модель пристрою чи код | ввести значення |
| `Допустимі значення: Low, Normal, High, Urgent.` | пріоритет чи стан не з переліку | ввести одне зі значень, регістр не важливий |
| `Введіть дату у форматі дд.мм.рррр…` | дата звіту в іншому форматі | наприклад, `25.11.2026` або Enter для сьогоднішньої |
| `Введіть суму, наприклад 450.50.` | сума оплати не число | ввести суму; кома й крапка рівноцінні |
| `Не додано: Коду «…» немає в прейскуранті.` | неіснуючий код | перевірити код (розділ 2) і повторити пункт 2 |
| `Відмовлено: Заявки № … немає.` | неіснуючий номер заявки | знайти номер через пункт 5 |
| `Відмовлено: Перехід зі стану … заборонено…` | перехід не дозволено таблицею станів | дотримуватися порядку Received → InWork → Ready → Issued |
| `Відмовлено: Позиції додають лише до нової квитанції.` | заявка вже в роботі | позиції додаються до початку ремонту |
| `Відмовлено: Сума … менша за вартість … грн.` | клієнт сплатив менше | прийняти повну суму; стан не змінився |
| `Помилка файлу або вводу: …` | `data/tickets.json` зайнятий іншою програмою чи недоступний | закрити програму, що тримає файл; код завершення 3 |
| `Непередбачений збій, деталі в repairservice.log.` | пошкоджений `data/tickets.json` або помилка в коді | прочитати останній рядок журналу, відновити файл із копії; код завершення 2 |

Кожна відмова записується в журнал на рівні Warning.

## 5. Дані, журнал і резервна копія

- Заявки: `data/tickets.json` у теці, з якої запущено застосунок. Файл
  перезаписується після кожної зміни.
- Журнал: `repairservice.log` — рядок на подію: час, рівень, сценарій
  (UC-01…UC-06) і повідомлення.
- Резервна копія — скопіювати файл, коли застосунок закрито:

```powershell
Copy-Item data\tickets.json "data\tickets-$(Get-Date -Format yyyyMMdd).json"
```

Щоб відновити, закрийте застосунок і скопіюйте копію назад у
`data\tickets.json`.
