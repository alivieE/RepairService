# 4. Дані: змінні, константи, типи, гроші й дати

## 4.1. Змінні

**D-01. Змінну оголошують якнайближче до першого використання.**
- **Рівень:** РЕКОМЕНДОВАНО.
- **Обґрунтування:** що коротша відстань між оголошенням і використанням,
  то менше рядків читач тримає в голові; змінна з початку довгого методу
  часто виявляється непотрібною в половині гілок.
- **Порушення:** усі змінні методу оголошено в першому рядку, як `decimal sum1 = 0; int kolvo = 0;`
- **Дотримання:** `decimal total = TotalOf(ticket);` безпосередньо перед порівнянням із сумою оплати.
- **Перевірка:** R-05.

**D-02. Змінну ініціалізують під час оголошення.**
- **Рівень:** РЕКОМЕНДОВАНО.
- **Обґрунтування:** неініціалізована змінна змушує шукати всі гілки, де їй
  присвоюють значення; компілятор не дозволить прочитати її, але читачеві від
  цього не легше.
- **Порушення:** `decimal rate;` і далі ланцюг `if`, кожна гілка якого присвоює `rate`.
- **Дотримання:** `decimal rate = PriorityRules.SurchargeOf(priority);`
- **Перевірка:** компілятор (CS0165), R-05.

**D-03. `var` — лише коли тип видно праворуч; для вбудованих типів — явний тип.**
- **Рівень:** РЕКОМЕНДОВАНО.
- **Обґрунтування:** `var ticket = new RepairTicket(...)` нічого не ховає, а
  `var total = service.TotalOf(ticket)` змушує вгадувати, `decimal` це чи
  `double`. Для грошей тип має бути видно завжди.
- **Порушення:** `var total = service.TotalOf(ticket);`
- **Дотримання:** `decimal total = service.TotalOf(ticket);`, `var line = new RepairWork("WKR-1", 1, 250m);`
- **Перевірка:** `csharp_style_var_*`, рівень suggestion (IDE0007, IDE0008).

**D-04. Одна змінна — одне призначення; невикористаних змінних, параметрів і приватних членів немає.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** змінна, у якій спочатку лежить сума робіт, а потім
  загальна сума, бреше в половині методу. Невикористаний член — це мертвий
  код, який доводиться читати.
- **Порушення:** `int notUsed = 0;`, параметр, який метод ігнорує.
- **Дотримання:** окремі змінні `works` і `total`; параметр або використовують, або прибирають.
- **Перевірка:** IDE0059, IDE0060, IDE0051, IDE0052, CS0219, error.

**D-05. Однолітерне ім’я — лише для лічильника циклу (`i`, `j`).**
- **Рівень:** РЕКОМЕНДОВАНО.
- **Обґрунтування:** лічильник живе кілька рядків, і його зміст очевидний;
  будь-яка інша однолітерна змінна змушує розшифровувати її.
- **Порушення:** `decimal c = decimal.Parse(ln[i][2]);`
- **Дотримання:** `for (int i = 0; i < lines.Count; i++)`, але `decimal unitPrice = lines[i].UnitPrice;`
- **Перевірка:** R-02.

## 4.2. Константи

**D-06. Числові й рядкові літерали в логіці замінюють іменованими константами.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** `0.9m` у формулі не каже, що це знижка 10 % постійному
  клієнту, а при зміні знижки треба знайти всі місця з `0.9m`. Винятки: `0`,
  `1`, `0m`, `1m`, порожній рядок і тексти повідомлень для користувача.
- **Порушення:** `if (f == true && sum1 > 1000) { sum1 = sum1 * 0.9m; }`
- **Дотримання:** `if (isRegularCustomer && total > RegularDiscountThreshold)` і `total *= 1m - RegularDiscountRate;`
- **Перевірка:** R-05.

**D-07. Поле, яке не змінюють після конструктора, — `readonly`.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** `readonly` гарантує, що залежність сервісу не підмінять
  посеред роботи, і читачеві не треба шукати присвоєнь.
- **Порушення:** `private IRepairTicketRepository _repository;`
- **Дотримання:** `private readonly IRepairTicketRepository _repository;`
- **Перевірка:** IDE0044, error.

**D-08. `const` — для значень, відомих під час компіляції; обчислюване значення — приватна статична властивість.**
- **Рівень:** РЕКОМЕНДОВАНО.
- **Обґрунтування:** `const` вбудовується в місце використання, тому годиться
  лише для незмінних чисел і рядків. Поле `static readonly` в проєкті конфліктує:
  N-09 вимагає `_camelCase`, а StyleCop SA1311 — великої літери. Тому дату чи
  культуру оголошують властивістю-виразом.
- **Порушення:** `private static readonly CultureInfo Ukrainian = CultureInfo.GetCultureInfo("uk-UA");`
- **Дотримання:** `private static CultureInfo Ukrainian => CultureInfo.GetCultureInfo("uk-UA");`
- **Перевірка:** R-05.

**D-09. Фіксований набір варіантів — перелічення; значення, які бізнес змінює без релізу, — дані.**
- **Рівень:** РЕКОМЕНДОВАНО.
- **Обґрунтування:** пріоритетів чотири, і додати п’ятий без зміни коду
  неможливо, тому це перелічення. Ціни робіт змінюються щомісяця, тому вони
  живуть у прейскуранті (`ServiceItem`), а не в константах.
- **Порушення:** `private const decimal ScreenReplacementPrice = 1200m;`
- **Дотримання:** ціна з довідника `ServiceItem.Price`; `enum TicketPriority { Low, Normal, High, Urgent }`
- **Перевірка:** R-05.

## 4.3. Типи

**D-10. Кількість і номер — `int`; `long`, `short` і беззнакові типи — лише з причиною в коментарі.**
- **Рівень:** РЕКОМЕНДОВАНО.
- **Обґрунтування:** `int` вистачає на 2 млрд заявок; змішування `int` і
  `uint` дає явні перетворення в кожному виразі.
- **Порушення:** `public uint Quantity { get; }`
- **Дотримання:** `public int Quantity { get; }`
- **Перевірка:** R-05.

**D-11. `Nullable` увімкнено; `?` ставлять лише там, де `null` — допустиме значення; оператор `!` — лише в тестах.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** компілятор попереджає про розіменування `null` до
  запуску. `!` вимикає цю перевірку, тому в робочому коді він ховає дефект.
- **Порушення:** `string name = request.Client!.Name;`
- **Дотримання:** `ArgumentNullException.ThrowIfNull(request.Client);` і далі `request.Client.Name`.
- **Перевірка:** `Nullable = enable` і `TreatWarningsAsErrors` (CS8600–CS8604 — помилки), R-05 для `!`.

**D-12. Ключові слова мови замість типів бібліотеки: `int`, `string`, `decimal`.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** `Int32` і `int` — той самий тип; змішування двох записів
  лише заважає пошуку.
- **Порушення:** `Int32 count = String.Empty.Length;`
- **Дотримання:** `int count = string.Empty.Length;`
- **Перевірка:** IDE0049, error.

**D-13. Публічна колекція — `IReadOnlyList<T>` або `IReadOnlyCollection<T>`; змінюваний список лишається приватним.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** якщо `RepairTicket.Lines` повертає `List<RepairWork>`,
  будь-хто додасть позицію повз `AddLine` і обійде перевірку стану заявки.
- **Порушення:** `public List<RepairWork> Lines { get; } = new();`
- **Дотримання:** `private readonly List<RepairWork> _lines = new();` і `public IReadOnlyList<RepairWork> Lines => _lines.AsReadOnly();`
- **Перевірка:** R-06.

**D-14. `List` — коли важливий порядок; `Dictionary` — пошук за ключем; `HashSet` — перевірка унікальності.**
- **Рівень:** РЕКОМЕНДОВАНО.
- **Обґрунтування:** пошук заявки за номером у `List` — це перебір усіх
  елементів; у сховищі заявок ключ — номер, тому там `Dictionary<int, RepairTicket>`.
- **Порушення:** `tickets.First(t => t.Id == id)` у сховищі на тисячі заявок.
- **Дотримання:** `_ticketsById.TryGetValue(id, out RepairTicket? ticket)`
- **Перевірка:** R-06.

**D-15. Стан і код документа — перелічення, а не рядок чи число.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** рядок `"InWrok"` компілюється, `TicketStatus.InWrok` — ні.
  Наряд `WorkOrder` (ЛР2) досі зберігає стан як `int` — це борг TD-08.
- **Порушення:** `public int Status { get; private set; }` зі значеннями 0–3.
- **Дотримання:** `public TicketStatus Status { get; private set; }`
- **Перевірка:** R-05.

## 4.4. Гроші й час

| Питання | Рішення в RepairService | Обґрунтування |
|---|---|---|
| тип суми | `decimal` | десятковий дріб без похибки подвійної точності |
| заборона | `double`, `float` у грошах | `0.1 + 0.2` у `double` не дорівнює `0.3` |
| літерал | обов’язковий суфікс `m` | без нього літерал має тип `double` і не компілюється в `decimal` |
| округлення | до 2 знаків, `MidpointRounding.AwayFromZero` | як у касі: 0,345 → 0,35; типове округлення C# дало б 0,34 |
| момент округлення | один раз, на вартості заявки (`TotalOf`) | інакше сума позицій не збігається з підсумком у квитанції |
| валюта | одна — гривня; одиниця в документації (`грн`) | сервіс працює лише в Україні; друга валюта — це новий тип `Money` і запис у журналі рішень |
| дата | `DateOnly` | дата прийняття й дедлайн — дні, без часу доби |
| момент у часі | `DateTimeOffset` | журнал аудиту: момент із часовим поясом |
| тривалість | `TimeSpan` або ціле число днів з одиницею в імені | строк ремонту рахують у днях: `DaysFor` |
| «сьогодні» | `IClock` | логіку можна перевірити тестом на будь-яку дату |

**D-16. Гроші — лише `decimal` із суфіксом `m`; `double` і `float` у грошових обчисленнях заборонено.**
- **Рівень:** ЗАБОРОНЕНО (`double`, `float`).
- **Обґрунтування:** двійковий дріб не зберігає копійки точно, і підсумок
  розходиться з чеком на копійку.
- **Порушення:** `double price = 199.99;`
- **Дотримання:** `decimal price = 199.99m;`
- **Перевірка:** компілятор (CS0664 для літерала без `m`), R-05.

**D-17. Суму округлюють до копійок за правилом «половина — від нуля» один раз, на підсумку заявки.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** `Math.Round` за замовчуванням округлює до парного
  (банківське округлення), а каса — від нуля. Округлення кожної позиції
  окремо дає розбіжність із підсумком.
- **Порушення:** `return Math.Round(total, 2);` у `WorkOrder.CalculateTotal` (борг TD-09).
- **Дотримання:** `return Math.Round(total, 2, MidpointRounding.AwayFromZero);` у `PriorityRules.TotalOf`.
- **Перевірка:** тест `TotalOf_ByPriority_MatchesDecisionTable` (рядок 0,30 → 0,35), R-05.

**D-18. Валюта одна — гривня; суми без валюти в іменах не позначають, одиницю пишуть у документації.**
- **Рівень:** РЕКОМЕНДОВАНО.
- **Обґрунтування:** поки валюта одна, тип `Money` лише ускладнить кожну
  формулу. Коли з’явиться друга валюта, правило замінюють записом журналу рішень.
- **Порушення:** `decimal amountUah`, `decimal totalInHryvnia`
- **Дотримання:** `decimal amount` і `/// <param name="amount">Сплачена сума, грн.</param>`
- **Перевірка:** R-05.

**D-19. Культуру форматування й спосіб порівняння рядків указують явно.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** `ToString()` для `decimal` на машині з англійською
  культурою дасть крапку, на українській — кому; звіт у конвеєрі й локально
  виходить різним.
- **Порушення:** `email.Contains('@')`, `price.ToString()`
- **Дотримання:** `email.Contains('@', StringComparison.Ordinal)`, `price.ToString("0.00", CultureInfo.InvariantCulture)`
- **Перевірка:** CA1305, CA1307, error.

**D-20. Типи часу: дата — `DateOnly`, час доби — `TimeOnly`, момент — `DateTimeOffset`, тривалість — `TimeSpan`.**
- **Рівень:** РЕКОМЕНДОВАНО.
- **Обґрунтування:** `DateTime` змішує дату, час і невизначений часовий пояс;
  для дедлайну зайвий час доби дає помилку «прострочено о 00:01».
- **Порушення:** `public DateTime CreatedAt { get; }` у новому коді.
- **Дотримання:** `public DateOnly CreatedAt { get; }`
- **Перевірка:** R-05.

**D-21. `DateTime.Now`, `DateTime.Today` і `DateTime.UtcNow` у `RepairService.Core` заборонено; «сьогодні» отримують через `IClock`.**
- **Рівень:** ЗАБОРОНЕНО.
- **Обґрунтування:** метод, що сам читає годинник, неможливо перевірити
  тестом на конкретну дату: тест «прострочено вчора» проходитиме лише в
  певні дні. Наряд `WorkOrder` досі читає `DateTime.Now` у конструкторі (борг TD-10).
- **Порушення:** `CreatedAt = DateTime.Now;`
- **Дотримання:** `CreatedAt = clock.Today;`, де `clock` — `IClock`.
- **Перевірка:** R-05; пошук `git grep -n "DateTime.Now" -- RepairService.Core`.

**D-22. Інтервал дат — напіввідкритий; якщо межа включна, це видно з імені.**
- **Рівень:** РЕКОМЕНДОВАНО.
- **Обґрунтування:** суфікс `Exclusive` знімає питання «чи входить
  кінцевий день». Дедлайн у RepairService — останній день строку включно, і
  це зафіксовано в глосарії та правилі X-05.
- **Порушення:** `DateOnly From, To` без пояснення меж.
- **Дотримання:** `DateOnly StartDate` і `DateOnly EndDateExclusive`; `Deadline` — включно.
- **Перевірка:** R-05.

**D-23. Ім’я дати має суфікс змісту: момент — `…At`, день — `…On` або `…Date`, кінець строку — `Deadline`.**
- **Рівень:** РЕКОМЕНДОВАНО.
- **Обґрунтування:** `Date1` і `dt` не кажуть, що це за дата; `CreatedAt`,
  `PaidAt`, `Deadline` читаються без коментаря.
- **Порушення:** `public DateTime dt;`
- **Дотримання:** `public DateOnly CreatedAt { get; }`
- **Перевірка:** R-02.

**D-24. Цільовий `new()` і ініціалізатори колекцій.**
- **Рівень:** ДОПУСКАЄТЬСЯ.
- **Обґрунтування:** `private readonly List<RepairWork> _lines = new();` і
  `new List<RepairWork>()` однаково зрозумілі, коли тип названо ліворуч.
- **Перевірка:** не перевіряють.

## 4.5. Акцент варіанта № 11: пріоритети заявок і розрахунок дедлайну

Строк ремонту й надбавка залежать від пріоритету за таблицею 1 специфікації
(`docs/spec.md`): Low — 10 днів, 0 %; Normal — 5 днів, 0 %; High — 2 дні, 15 %;
Urgent — 1 день, 30 %. Саме тут найлегше помилитися: переплутати день,
надбавку чи межу дедлайну.

**X-01. Пріоритет — лише перелічення `TicketPriority`; прапорці `isUrgent`, числа й рядки заборонено.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** булевий прапорець описує два стани з чотирьох; число 2
  в одному методі означає High, а в іншому — кількість днів. `RepairCostPolicy`
  з ЛР7 ще приймає `bool isUrgent` — це борг TD-11.
- **Порушення:** `LineCostFor(decimal unitPrice, int quantity, bool isUrgent)`
- **Дотримання:** `TotalOf(IEnumerable<RepairWork> lines, TicketPriority priority)`
- **Перевірка:** R-07.

**X-02. Дедлайн заявки обчислюють лише через `PriorityRules.DeadlineOf`.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** якщо додавати дні «на місці», то після зміни таблиці 1
  частина коду рахуватиме за старими строками.
- **Порушення:** `ticket.Deadline = createdAt.AddDays(2);`
- **Дотримання:** `ticket.Deadline = PriorityRules.DeadlineOf(createdAt, priority);`
- **Перевірка:** R-07, тест `DeadlineOf_ByPriority_AddsDays`.

**X-03. Строки й надбавки живуть лише в константах `PriorityRules`; `switch` за пріоритетом закінчується гілкою з винятком.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** таблиця рішень має одне джерело; гілка `_ => throw`
  не дасть мовчки повернути 0 днів, якщо з’явиться п’ятий пріоритет.
- **Порушення:** `decimal surcharge = priority == TicketPriority.Urgent ? 0.3m : 0m;` у сервісі.
- **Дотримання:** `decimal surcharge = PriorityRules.SurchargeOf(priority);`
- **Перевірка:** R-07, тести `SurchargeOf_ByPriority_MatchesDecisionTable`, `DaysFor_UnknownPriority_Throws`.

**X-04. Надбавку за пріоритет нараховують лише на роботи (`LineKind.Work`), запчастини не дорожчають.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** терміновість оплачує час майстра, а ціна деталі від
  поспіху не залежить; помилка тут завищує рахунок клієнта.
- **Порушення:** `total = Math.Round(lines.Sum(l => l.Amount) * (1m + surcharge), 2);`
- **Дотримання:** окремі суми `works` і `parts`, надбавка лише до `works`, округлення в кінці.
- **Перевірка:** тест `TotalOf_ByPriority_MatchesDecisionTable` (рядок Urgent, роботи 0, запчастини 500 → 500).

**X-05. `Deadline` — останній день строку включно; заявка прострочена, якщо дата звіту пізніша за дедлайн; дату звіту передають явно.**
- **Рівень:** ОБОВ’ЯЗКОВО.
- **Обґрунтування:** за умови `>=` замість `>` терміновий ремонт став би
  простроченим уже в день дедлайну; явна дата робить перевірку чистою функцією.
- **Порушення:** `public bool IsOverdue() => DateTime.Today >= Deadline;`
- **Дотримання:** `public bool IsOverdueOn(DateOnly reportDate) => reportDate > Deadline && Status is TicketStatus.Received or TicketStatus.InWork;`
- **Перевірка:** R-07, тести `Overdue_TicketPastDeadline_Included`, `Overdue_ReadyTicket_Excluded` (СР3).

## 4.6. Пари прикладів

**Пара 17. Гроші в `double` (D-06, D-16, D-17).**

```csharp
// ПОГАНО
double price = 250.5;
double total = price * 2;
total = total + total * 0.3;
if (total == 651.3) { ... }
```

```csharp
// ДОБРЕ
private const decimal UrgentSurcharge = 0.30m;

decimal works = 250.50m * 2;
decimal total = Math.Round(
    works * (1m + UrgentSurcharge),
    2,
    MidpointRounding.AwayFromZero);
```

У `double` результат 651.3000000000001, тому порівняння з 651.3 хибне; число
0.3 не каже, що це надбавка за терміновість.

**Пара 18. Дата з годинника всередині логіки (D-20, D-21, D-23, X-05).**

```csharp
// ПОГАНО
public DateTime d1;
public DateTime d2;
public int t; // 1 — звичайний, 2 — терміновий

public bool Late() => DateTime.Now > d2;
```

```csharp
// ДОБРЕ
public DateOnly CreatedAt { get; }
public DateOnly Deadline { get; }
public TicketPriority Priority { get; }

public bool IsOverdueOn(DateOnly reportDate) => reportDate > Deadline;
```

Явна дата звіту робить метод чистою функцією: тест перевіряє «прострочено»
за мілісекунду на будь-яку дату. Перелічення замість `int t` робить
неможливими значення 3 і 17.

**Пара 19. Публічний змінюваний список (D-13).**

```csharp
// ПОГАНО
public List<RepairWork> Lines { get; } = new();
// десь у застосунку:
ticket.Lines.Add(new RepairWork("WKR-1", 1, 250m));
```

```csharp
// ДОБРЕ
private readonly List<RepairWork> _lines = new();
public IReadOnlyList<RepairWork> Lines => _lines.AsReadOnly();

public void AddLine(RepairWork line)
{
    EnsureStatus(TicketStatus.Received);
    _lines.Add(line);
}
```

Перший варіант дозволяє додати позицію до вже виданої заявки; другий
пропускає зміни лише через метод, який перевіряє стан.

**Пара 20. Число замість перелічення для пріоритету (X-01, X-02, X-03).**

```csharp
// ПОГАНО
public DateOnly DeadlineOf(DateOnly createdAt, int priority)
{
    if (priority == 3) return createdAt.AddDays(1);
    if (priority == 2) return createdAt.AddDays(2);
    return createdAt.AddDays(5);
}
```

```csharp
// ДОБРЕ
public static DateOnly DeadlineOf(DateOnly createdAt, TicketPriority priority) =>
    createdAt.AddDays(DaysFor(priority));
```

У першому варіанті пріоритет Low мовчки отримує 5 днів замість 10, а
значення 7 не викликає помилки. Другий бере дні з єдиної таблиці `DaysFor`,
яка кидає виняток на невідомий пріоритет.
